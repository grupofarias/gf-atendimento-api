🤖 Setup n8n
Passo a passo para conectar Chatwoot + n8n + Middleware. Siga a ordem abaixo e depois importe o workflow de modelo.
1
Chatwoot · Admin
Criar o AgentBot
No painel admin do Chatwoot, acesse Settings → Integrations → Agent Bots e clique em New Agent Bot.
Nome: ex. GF AI Bot
Endpoint URL: cole a URL do webhook gerada pelo n8n — ex. https://SEU_N8N/webhook/SEU_PATH
Salvar. O Chatwoot vai enviar eventos para este endpoint automaticamente.
2
Chatwoot · Settings
Associar AgentBot à Inbox
No painel admin do Chatwoot, vá em Settings → Inboxes, clique no ícone de engrenagem (Settings) da inbox desejada, abra a aba Configuration e localize o campo Agent Bot.
Selecione o bot criado no passo anterior e salve.
A partir daí o Chatwoot dispara message_created para o n8n em toda nova mensagem incoming nessa inbox.
3
n8n · Webhook Node
Criar o Webhook no n8n
No workflow, o primeiro nó é um Webhook com método POST. A URL gerada pelo n8n é o que você colará no AgentBot do Chatwoot.
Path: qualquer nome único — ex. chatwoot-handler-prod
Authentication: none (o Chatwoot não envia token de autenticacão por padrão neste modo)
O nó já está configurado no JSON de modelo abaixo.
4
n8n · If Node
Filtrar bot-off antes de chamar o middleware
Após o Webhook, o primeiro If checa se a label bot-off está presente nas labels da conversa no payload bruto do Chatwoot. Se sim, o fluxo encerra e o Redis é limpo — sem gastar chamada no middleware.
Condição: $json.body.conversation.labels contém “bot-off”
True (branch 1): nó Redis DELETE — apaga a chave accountId-inboxId-contactId
False (branch 2): continua para POST /normalize
If — bot-off na label?
Redis DELETE (limpar memória)
5
n8n → Middleware
POST /normalize
Nó HTTP Request chama POST https://SEU_TUNNEL_URL/normalize com o body bruto do Chatwoot. O middleware retorna um InternalMessage normalizado.
Header: x-api-key: SUA_MIDDLEWARE_API_KEY (valor de MIDDLEWARE_API_KEY no .env do middleware)
Body: JSON.stringify($json.body)
Retorno quando deve ignorar: { skip: true, reason: “...” }
Retorno quando processa: { skip: false, message: { conversationId, phone, text, labels, ... } }
6
n8n · If Node
Filtrar skip=false e messageType=incoming
Segundo If combina duas condições com AND: descarta mensagens outgoing e qualquer caso em que o middleware pediu skip.
Cond. 1: $json.skip === false
Cond. 2: $json.message.messageType === “incoming”
Só o ramo true segue para o AI Agent.
7
n8n · AI Agent
AI Agent (GPT-4o-mini + Redis Chat Memory)
O AI Agent recebe o contexto da conversa e decide quais tools chamar. Ele só se comunica com o cliente via tools — nunca pelo output final do nó.
Modelo: gpt-4o-mini — configurar credencial OpenAI
Memória: Redis Chat Memory — sessionKey = accountId-inboxId-contactId
TTL sessão: 60000 ms · Janela de contexto: 10 mensagens
Memória Redis: configurar credencial Redis no n8n e selecionar nos nós Redis e Redis Chat Memory
send_message
handoff_to_human
add_labels
set_status
get_agents
8
AI Agent → Middleware
Tools chamam o middleware via HTTP
Cada tool é um nó HTTP Request Tool conectado ao AI Agent. A URL usa $('HTTP Request').item.json.message.conversationId para montar o path dinamicamente.
Header em todas: x-api-key: SUA_MIDDLEWARE_API_KEY
Ordem obrigatória no handoff: 1) get_agents (se precisar de ID) → 2) handoff_to_human → 3) send_message avisando o cliente
